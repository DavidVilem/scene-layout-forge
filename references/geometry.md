# Geometry helpers and evidence boundaries

The pinned runtime in `requirements.txt` requires Python 3.11+; it has been tested with Python 3.13.13. Install it in a project virtual environment using `python -m pip install -r <skill-folder>/requirements.txt`. NumPy and Pillow are dependencies, not bundled copies. The calculated renderer itself uses no API, credentials or network. Run the scripts from their installed location; create scene files and output in the project, not in this package. Installing dependencies may require package-index access; rendering after installation does not.

## Connected example

Run examples with the project as the working directory. The `scripts/...` paths below abbreviate the installed skill's scripts: replace them with absolute paths to that installation. Do not change into the skill folder to run these examples, because their scene/output paths are relative to the current directory.

```sh
python -B scripts/connected_plant.py --out scene.json
python -B scripts/render_scene.py --scene scene.json --out review.png --width 1600 --height 1200
```

This original fixture contains two vessels, one pump, one stair, one landing and two simplified workers. It is a test case, not a universal scene template. `industrial_fixture.py` supplies isolated elbow/sweep tests. For a building study, `render_scene.py --floors 16 --out review.png` generates a tower.

## Model and adapters

`scene_model.py` stores parts with `id`, `kind`, `origin`, `size`, optional `parent`, local `ports` and `parameters`. Connections use `from`/`to` strings in `part:port` form, a world-space `route`, positive `radius`, and optional `fittings: true` for endpoint flanges. Routes render from the same data used for endpoint validation.

`scene_schema.py` checks container shapes and required field types before geometric validation. It rejects malformed relationship records, nonfinite values, boolean radii, invalid detail vectors and unknown count kinds with field-specific errors. `validate` returns an error list; `build` raises a readable `ValueError` if that list is nonempty. This preflight is not a proof that arbitrary numeric extremes or every possible scene can render successfully; rendering and visual checks remain separate gates.

The original 31 kinds build geometry; 12 additional technical adapters are documented in [component-catalog.md](component-catalog.md). The original adapters cover: structural boxes; diagonal braces; wedge corbels and ramps; framed windows/doors; facade panels with mullions; vessel bodies, legs and bands; simplified pump/motor; circular pipe/conduit sweeps; valves and flanges; horizontal manifolds; stairs, railings and schematic workers; vented cabinets; grated drains; open cable trays; hollow ducts; planters and bollards. `architectural_parts.py` supplies the architectural/service adapters. Some are deliberately schematic, and this coverage does not establish finished detail quality. Window/door/cabinet fronts face +Y; ducts and trays run along +Y. Rotation is not yet a general part parameter.

The renderer has orthographic auto-fit projection, per-pixel depth buffering, cylinder silhouettes, drawing-plane pencil hatching and seeded paper grain. Hatching changes surface tone only, not geometry or visibility. `Mesh.flange` builds oriented flanges with bolts. Sweep points must be finite, distinct and must not reverse direction; smooth elbow samples can be created with `industrial_fixture.elbow`. Arbitrary sharp corners are not automatically replaced with tangent elbows.

Validation checks IDs, basic dimensions, parent references/cycles, declared counts, connection endpoints, selected AABB clearance pairs, and supported worker footing. Optional `bearings` entries (`part`, `on`) check vertical contact and overlapping footprints. Optional `stair_access` entries (`stair`, `landing`) check full stair width, landing edge and elevation for +Y/-Y stairs, plus explicit railing interference at the entrance. `route_obstacles` lists IDs checked against every connection segment using radius-expanded AABBs; this is conservative near corners. Undeclared contacts and obstacles are not checked. It does not solve hydraulic flow or certify structures. Detailed curvature, route-clearance and entrance-check limits are below. Worker meshes are schematic; fine details require visual inspection. The calculated artwork is a geometric study; the generative artistic finish is a separate reviewed stage.

## Multi-section factory

`python -B scripts/factory.py --bays 3 --out factory.json` creates six vessels, three pumps and six workers across three processing sections. It remaps IDs, ports, worker parents and constraints and joins headers with tangent elbow paths above stair access. The risers offset toward the aisle to separate them from tray-support silhouettes. Each pump inlet is on the top of the actual casing surface, reached by a short curved rising branch so the junction is visible from above. These are fixture layout decisions, not mandatory port locations for every pump design. Cabinets, cable trays and tray supports add service detail. Data validation covers 1, 3 and 12 sections; actual full render tests cover 3 sections. This repeatable assembly is not evidence of arbitrary factory topology or load-bearing adequacy. Use it as a starting point, then design the requested site's unique equipment and circulation.

The factory example also declares tray support posts as route obstacles. Its front posts and tray lengths are placed together to improve junction visibility while retaining actual bearing contact. These scene choices do not guarantee a clear view at every camera or in a later generative image; inspect silhouettes after moving any structural member.

Use `factory.py --enclosed` for an entrance-open hall with an aisle-side wall, far end wall and roof slabs supported by rear/front frames and transverse beams. The equipment network stays unchanged; new roof and wall obstacles and bearing relationships are validated. The enclosure is an architectural study, not a complete building-services or structural design. An interior camera naturally hides some components; it cannot also serve as proof that every connection is visible.

## Detailed high-rise assembly

`python -B scripts/highrise.py --floors 24 --bays 3 --out highrise.json` creates the structural tower plus an entrance replacing one ground-floor facade panel, landing, reversed access ramp, supported canopy, parapets, rooftop service cabinets, facade fins, paving, planters and bollards. Render with `render_scene.py --scene highrise.json --out review.png --width 1000 --height 1700`. The generator accepts 1..100 floors and 2..12 bays, inherited from the structural model; data tests cover 4/24/60 floors with several bay counts and the detailed render test covers 12 floors. A 24-floor composition has also been visually reviewed. Do not infer building-code, evacuation, accessibility or structural certification from this conceptual exterior model.

Ramp parts accept `parameters.reverse: true` for a high edge at the lower Y coordinate. Optional `ramp_access` entries use `ramp` and `landing` IDs and check the same landing-edge, full-width and height relationship as stairs. Roof equipment, canopy columns and facade fins declare bearing relationships. Hidden interiors and arbitrary tower setbacks are not generated by this example.

## Optional architectural detail

Part `parameters` can add original procedural details without image assets:

- Column `profile: "steel"`: inset rectangular shaft, baseplate and four hexagonal anchor-bolt heads, all within the declared bounding box. It is a schematic steel column, not a standardized engineered section.
- Wall `panel_size: [width, height]`: regular panel joints on the +Y surface. Values are metres; a grid above 1000 joint lines is rejected.
- Landing `surface: "grating"`, `grid_spacing: 0.12`: regular grid marks on the supported top slab, not actual openings. A grid above 2000 lines is rejected.
- Vessel `inspection_hatch: true` and `seam_bolts: 16`: an inspection-cover outline and fixing marks mapped onto the cylindrical shell. `seam_bolts` accepts integers 0..64 and defaults to 0; the hatch is off by default. These are surface drawing details, not protruding bolts, a working hatch or a cutout. They add no volume and preserve depth/ownership. The hatch faces +Y at roughly 60% of vessel height; omit it if that area is occupied by a custom port or another feature. The connected example opts in explicitly. No artwork is embedded: `surface_details.py` computes each mark from the vessel's actual radius and height.

The connected-plant fixture opts into these details; unrelated scenes retain their own defaults. Choose spacing for output scale and inspect for clutter. Dimension/contact validation does not establish bolt capacity or structural adequacy.

## Camera and calculated annotations

Both `render_scene.py` and `generate_design.py` accept `--finish graphite`. The default `technical` remains compatible with previous output. Graphite changes only drawing appearance: lighter face washes, variable pressure on fill strokes, depth-dependent contour ink, seeded procedural paper grain and softer cast-shadow tones. Contour positions, depth buffers, part ownership, route visibility and the scene itself are unchanged. `drawing_style.py` computes these marks from code; it loads no reference images or permanent textures. A repeated render at the same settings is reproducible. This remains a calculated drawing: it does not create natural workwear detail or the full irregular richness of a skilled artist's layout. Inspect the result rather than describing the mode name as proof of reference-style fidelity.

Use `--azimuth 60 --elevation 22` to change the orthographic view without modifying world geometry. Angles are in degrees; elevation accepts 5..90; 90 with orthographic projection gives a top-down plan. The default retains the original diagonal view. Choose a view that exposes required junctions before artistic polishing. Camera choice is not automatic visibility optimization.

Use `--projection perspective` for calculated vanishing-point convergence; the default remains `orthographic`. Perspective uses reciprocal camera depth, view-dependent curved silhouettes and inverse projection for shadow lookup. With no explicit eye/target, auto-fit places the camera outside the full scene bounds. A lower elevation can bring that view closer to a background-layout composition, but inspect occlusions before accepting it. The world geometry, part IDs, connections and labels retain the same source data.

For a placed interior camera, both rendering commands accept `--projection perspective --eye X Y Z --target X Y Z --fov 60 --near 0.15`. Eye and target are world coordinates in metres; FOV is vertical degrees (10..120), and near is a positive camera distance. Supply eye and target together. This mode does not auto-fit: objects can be intentionally cropped or hidden. Faces and edges crossing the near plane are clipped before projection, and screen-space lines are clipped before sampling. It is camera clipping, not a modeled section cut with new cap surfaces. Endpoint neighborhoods behind the near plane report zero. To inspect the enclosed three-bay example, `--eye -3 6 1.8 --target 22 0 2.5 --fov 60 --near 0.15` gives a ground-level view through the entrance. Use `--no-shadows` for ambient-style interior studies when the directional exterior light would be blocked by the roof; the renderer does not yet simulate interior light fixtures.

Optional scene `labels` entries contain `target` (part ID), `text` (one line), and `position` (normalized image XY, top-left origin). For example: `{"target":"tank-0","text":"STORAGE VESSEL","position":[0.05,0.10]}`. The renderer records part ownership during depth rasterization and selects an actual visible target pixel for the leader endpoint. Hidden targets, unknown IDs, overlapping text, out-of-frame text, and text boxes covering geometry raise explicit errors. Leader paths can still cross other geometry; inspect and adjust text placement. Use `--title` for a meaningful English title and reserve its top strip when placing labels. Output JSON includes label anchors for inspection. This mechanism verifies the endpoint target, not whether a human-written label's wording is semantically correct.

`design_core.py` is a legacy fixed sample with painter sorting. Retained for existing callers; use `render_scene.py` for new supported scenes.

Legacy workers use ellipsoids for jacket, head, hands, boots and helmet, with swept limbs, and remain unchanged standing figures. The optional [seated/leaning pose adapters](actor-poses.md) generate static task geometry and typed surface contacts from one specification; they are not an articulated motion or biomechanics system. Ellipsoid silhouettes use shared-face adjacency without drawing every mesh facet. Hatching integrates stripe coverage over pixel footprints to reduce dotted aliasing without moving geometry.

Vessel legs, lid and circumferential seams scale with the declared dimensions; seams stay on the shell envelope instead of projecting outside its clearance bounds. The shell uses the smaller horizontal dimension as its diameter and remains centred in the footprint. Pump bases and fins also scale, with casing radius limited by width, depth and height. Pedestals support the casing/motor and a shaft bridges the two even in a long, shallow assembly. These are schematic equipment adapters, not manufacturer models. Define ports against the actual surfaces and recompute scene-specific port positions when changing dimensions; resizing a part does not automatically move arbitrary user-defined ports or attached routes.

The CLI exports with `--supersample 2` by default: geometry, line widths, margins and type are rendered at twice the requested dimensions, then resolved to the final size. Use 1 for fast inspection or 3 for finer export at greater memory/time cost. This is deterministic rendering, not generative restyling. It reduces raster stair-stepping but does not add missing architectural detail. JSON label anchors are reported in final-image pixels. Straight screen-plane hatching replaces the previous world-plane pattern that produced distracting waves on cylinders.

Contour visibility uses a conservative one-raster-pixel depth footprint to avoid disappearing tangent silhouettes when a cylinder moves by a subpixel amount. At 2x export that footprint is half an output pixel. This is a raster approximation, not exact analytic hidden-line removal; inspect crowded junctions. Tests include shifted cylinder contours, fully enclosed hidden geometry, and a foreground object hiding the middle of a contour.

CLI exports include restrained directional cast shadows from a second depth pass. Use `--no-shadows` for unshaded technical drawings or to inspect a suspected line defect. The Python renderer enables this via `shadows=True`. Shadowing changes surface tone only and runs before contour drawing; camera depth, part ownership and connection geometry remain unchanged. The fixed light is above the -X/+Y side. The shadow map is limited to 1200 pixels and uses a conservative bias, so fine contact shadows can soften/disappear and curved shadow boundaries can look faceted. It is not physically based lighting or global illumination.

## Meaningful checks

When two routes use different ports of the same `manifold`, exclude only their segments inside that component's bounding envelope expanded by the larger tube radius. Continue testing the remaining segments, including remote crossings. This models the local junction as a connection zone, not empty clearance. An oversized manifold envelope can hide conflicts; use its real dimensions. No such exemption is inferred for other shared equipment kinds.

Distinct connection routes are compared using their combined pipe radii and closest points on finite segments. Crossings at the same height and overlapping parallel runs are rejected; sufficient vertical separation is allowed. Broad-phase route and segment bounds avoid checking distant geometry. For an exact shared `part:port`, exclude a local box centred on the port with half-width twice the larger tube radius, then compare the remaining portions. A shared port never exempts an entire pair. Identical or reversed-identical sampled routes are rejected even inside junction zones. Inspect permitted zones and wider flanges separately: this is conservative capsule clearance, not a fitting or mesh certificate. `test_route_pairs.py` covers crossings, separation, parallel runs, shared-port branches with remote conflicts, long overlapping starts, duplicates, manifold zones and validator integration.

Connection validation checks distant segments of each route against that route's tube diameter (`check_route_self_clearance`). It uses closest points on finite 3D segments and excludes the local neighbourhood within pi times tube radius along the centreline; curvature is checked separately. Closed-route seams use cyclic distance. This conservative capsule test catches self-crossings and close parallel returns but is not a mesh-intersection proof. It does not compare separate routes or automatically create a junction at a crossing. Positive clearance at sparse samples does not certify an intended unsampled curve. `test_self_clearance.py` covers crossing/skew/parallel segment distances, invalid returns, an elevated crossing, dense valid elbows and closed circular seams.

Sampled tube bends are checked against their local three-point circumradius before mesh construction. A tube radius at least as large as that bend radius is rejected to avoid a folded inner surface. Connection routes receive the same check during scene validation. This does not smooth sharp corners or detect remote self-intersections; sparse waypoints cannot establish the curvature of an unsampled intended arc. Use `rounded_route` to explicitly sample tangent elbows, then check the actual tube radius. Tests cover invalid folds, valid smaller tubes and translated/rotated/scaled samples.

After drawing, `Renderer.component_visibility(scene)` returns per-component surface pixel counts and totals by component kind. CLI and `generate_design.py` expose this as `component_visibility`. Use it to locate components with zero visible surface before choosing an artistic guide. Counts come from depth-tested face ownership at `visibility_raster_size`, before final downsampling. A positive count does not mean the object is recognizable or fully visible; zero can mean occlusion, cropping, behind-camera placement or undersampling. It does not classify the cause or test contour-only marks. Do not transfer this calculated report to a generative finish. Route surfaces are excluded from component totals and remain in the separate connection report.
- `test_component_visibility.py`: one enclosed and one behind-camera component, a visible component of the same kind, aggregation, unchanged pixels/depth/ownership, and missing metadata rejection.

Declared `stair_access` and `ramp_access` relationships also check for explicit `railing` bars/posts crossing the landing entrance. `access_geometry.py` uses the same endpoints, post spacing and rail heights as the current adapter, including custom world-space `start`/`end`. The local test covers a central entrance slice from 0.10 to 1.80 metres above the landing, with 0.025-metre tube allowance; those are illustration-review tolerances, not code-compliance dimensions. It excludes side junctions and does not check a whole access corridor, headroom, doors, pipes, walls or railings on other parts. Inspect those separately. The built-in stair side rails are not separate railing parts and are not tested by this check.
- `test_access_geometry.py`: blocked forward/reversed stairs and ramps, custom endpoints, overhead bars with an obstructing post, unobstructed side/distant rails, and the connected-plant regression.

Graphite fill strokes adapt their pressure to surface tone and their direction to surface inclination. Light planes retain more blank paper; dark planes receive restrained crossing strokes. Spacing and phase stay independent of tone and horizontal normal angle to avoid broken stripes between vertical cylinder facets. The phase is shared across coplanar triangles and does not depend on winding or triangle IDs. This is screen-space illustration, not a physical graphite simulation or a surface texture. Other curved meshes can still reveal changes between facets; inspect large foreground curves. The fill does not perturb geometric contours.

For a new pipe centreline with straight waypoints, use `route_geometry.rounded_route(points, bend_radius, steps_per_quarter=12)`. It inserts circular tangent bends in each turn's plane, including nonplanar routes, while preserving the first and last coordinates exactly. Choose a bend radius larger than the tube radius to avoid a folded inner surface. It rejects repeated points, reversals and bends that cannot fit the available adjacent segment lengths; it does not silently reduce the requested radius. The default samples a quarter turn with 12 segments. Pass the resulting points as the connection `route`, then validate endpoint ports and clearances normally. This helper does not plan a route, avoid obstacles or check all self-intersections. Do not re-fillet an already sampled curved route. The connected plant and factory fixtures use it for pump-to-drain discharge bends.

The renderer and `generate_design.py` return a `connections` visibility report keyed by zero-based scene connection index and both port names. `visible_pixels` counts depth-tested surface pixels for that route including its fittings. `endpoint_neighborhood_pixels` counts route-owned pixels within projected fitting-sized neighborhoods at its two endpoints. Counts use the reported `visibility_raster_size` before downsampling. A zero identifies a hidden or undersampled feature that needs inspection or a different camera; a positive number only means some route surface is nearby, not that the endpoint is attached correctly or the entire route is unobstructed. The report applies to the calculated guide only, never to a subsequent generative image. Route ownership does not alter geometry, shading or depth.

When selecting a factory camera, compare endpoint neighborhoods as well as whole-route visibility: a long exposed pipe can hide its connection to a pump. Keep the specified components and topology while changing the camera. Confirm the actual guide visually and then retrace the finished image independently.

Repeat visibility inspection at the final aspect ratio, dimensions and supersampling setting. A few pixels in a low-resolution endpoint neighborhood can disappear at higher resolution as the fitting footprint and depth rasterization resolve differently. Do not turn a positive thumbnail measurement into an invariant camera guarantee.

For a calculated candidate with persistent execution history, run:

```sh
python -B scripts/generate_design.py --scene scene.json --out-dir work/design-candidate --width 1400 --height 1000
```

The destination must be new. The command snapshots the scene, renders and decodes the PNG in an owned history directory, then publishes one `ilustrada.png`. Existing outputs and supplied references are preserved. On failure the owned history directory is retained. It does not clean files produced by other tools: track those exact paths separately. Publication copies the selected image to a new directory and retains its historical source. Concurrent publication to the same destination is unsupported on other platforms. Success means schema/relationship validation and PNG decoding passed; visual acceptance remains pending. For a generative finish use this candidate as runtime guidance and follow the separate artistic review workflow.

- `test_workflow.py`: real subprocess rendering publishes one decodable image; invalid scene and render-time label failure publish nothing; prior output and input bytes survive; execution evidence is retained.
- `test_route_visibility.py`: visible and enclosed connections, an exposed pipe with one hidden endpoint, collision-free synthetic ownership IDs, and identical rendered pixels/depth before and after adding ownership metadata.
- `test_equipment_scale.py`: vessel and pump meshes stay inside declared envelopes at five varied dimension sets, with finite nondegenerate faces and ground contact; a long pump retains geometry across the previous casing-to-motor gap.
- `test_route_geometry.py`: constant circular bend radius, tangent transitions, nonplanar turns, exact port endpoints, and rejection of reversals or bends larger than available space.
- `test_drawing_style.py`: exact equality of depth, ownership and connection-visibility reports between technical and graphite modes (including shadows), visible tone changes, repeatable building output and rejection of an unknown finish.
- `test_surface_details.py`: detail vertices lie on the cylinder at varied dimensions, remain between the support and lid, keep depth/ownership unchanged, affect visible linework and reject invalid detail parameters before rendering.
- `test_interior_camera.py`: centred target and inverse projection, near-plane polygon/edge clipping, a straddling box, rejection of behind-camera geometry, bounded sampling of huge projected lines, hidden route-end reporting and invalid camera rejection.
- `test_scene_model.py`: valid and invalid contracts, counts, parent/port errors, tower data scale.
- `test_renderer.py`: depth/occlusion, vertical projection, order independence, tower rendering, hatching leaves depth/ownership unchanged, repeatability and supersampling preserves projected composition.
- `test_curves.py`: sweep radii, elbow endpoints, degenerate input rejection, flange geometry and industrial rendering.
- `test_assembly.py`: connected assembly, moved pump, floating worker and end-to-end render.
- `test_core.py`: legacy sample invariants.
- `test_perspective.py`: projection/inverse roundtrip, raster depth reconstructs onto actual box surfaces, nearer equal segments grow, enclosed geometry remains hidden, and a shadowed plant preserves visible part ownership.
- `test_schema.py`: malformed scene/part/relationship records, nonfinite and boolean radii, invalid detail parameters and a matrix of mutated fields return errors instead of validator crashes.
- `test_shadows.py`: cast-shadow direction, unchanged depth/ownership/background, and unoccluded floor-top samples remain unshadowed.

Test coverage is narrower than the full architectural design brief. Inspect at least one connected industrial composition and one building composition after relevant renderer changes; retain no review images in the package.

## Declared shaft and bearing interfaces

See [mechanical coherence](mechanical-coherence.md) for optional `shaft_bearings` validation and its limits. It checks straight cylindrical shaft geometry against annular bearing apertures; it does not infer these interfaces from arbitrary part names or simulate transmission. The supported-drive fixture exercises this check.
