# Execution policy — revision 17

Ordinary illustration requests use the general reviewed-illustration route in [SKILL.md](../SKILL.md) and [walkthrough](walkthrough.md). Existing strict geometry acceptance remains available only when requested explicitly. A missing adapter is not a global refusal condition for an illustration.

Create persistent history before work. Never delete originals, guides, intermediate scripts, failures or reviews automatically. Do not store them inside the skill. Annotations are off unless requested. Preserve the original prompt, exact finishing request, loaded source hashes, image-tool facts and limitations in each run.

Numerical failure: repair the supplied model before rendering or generation. Unsupported numerical property: disclose it, plan the visible relationship and inspect generated pixels; do not call it passed. No numerical model: record not_run and use explicit spatial planning plus independent visual review. Validating a guide does not validate the generated image. Never infer loads, pressure, hidden internals or functional performance from appearances.

The general path does not require implementing a new whole-subject materializer at runtime. Use supported primitives where helpful; essential silhouettes can be specified to the image generator in a structured spatial contract. Do not replace them with arbitrary boxes and call that geometry verified. In explicitly strict mode, missing required checkers still prevent strict acceptance.
