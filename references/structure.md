# Package organization

The entrypoint routes to task-specific references; the kit exposes local geometry code. Each executable example provides a scene, recipe, invocation prompt and builder. Worked cases explain choices and rejection conditions without pretending to be renderable fixtures. Evaluations separate numerical checks from visual acceptance.

All code and examples are original procedural source. No external artwork, private path or previous conversation is required. Dependencies are listed in requirements.txt. Generated files stay outside the package.

The deliverable is one PNG. Interactive applications, animation, exploded assemblies and publishing are outside the current scope. Geometry can be repeatable in a pinned environment; generated artwork is not guaranteed byte-identical.
